# UniVTAC Docker Tactile Validation

Use this skill for the pinned local UniVTAC Docker workflow. It is for diagnostic, bounded validation; do not use it to upgrade or downgrade Isaac Sim, change task physics, alter success criteria, or substitute model weights.

## Runtime invariants

- The working image is `user10/univtac-isaac60-lab3-tacex:ftp1-pytorch-runtime-fem-tactile-curobo-sm120-uipc-sm120-resetcache` (Isaac Sim 6). Keep that version unless the user explicitly changes the scope.
- Local source must be mounted over both installed packages, in addition to mounting `UniVTAC` at `/workspace/UniVTAC`:
  - `UniVTAC/third_party/TacEx/source/tacex/tacex` -> `/opt/tacex/source/tacex/tacex`
  - `UniVTAC/third_party/TacEx/source/tacex_uipc/tacex_uipc` -> `/opt/tacex/source/tacex_uipc/tacex_uipc`
  Without the first mount the stock package imports `isaacsim.core.prims`, which this image does not provide.
- On the 16 GB GPU, use one environment and headless mode. Apply a container RAM cap and make its swap limit equal to its RAM limit so a runaway run cannot consume host swap. Preserve stopped containers for diagnosis.
- Established guard: `--gpus all --memory=15g --memory-swap=15g --cpus=6 --pids-limit=512 --ulimit core=0 --shm-size=64m --user 1234:1000`. A host swap value by itself does not prove the container needs more RAM; inspect the capped container's memory, exit code, and `OOMKilled` state.
- Treat headless Hub/GLFW warnings as routine only after the task actually initializes; distinguish them from an OOM, a nonzero container exit, or a host freeze.

## Safe validation order

1. Run a single deterministic `collect` episode with `contact.yml`, `--headless --livestream 0`, and an opt-in `--validation-dir`. Run it in `tmux` only if the user has authorized that workflow.
2. Confirm container exit status, `OOMKilled`, peak/ending resource use, and saved t0/t1/t2/failure artifacts before any further task.
3. Run `--validation-tactile-sanity` before interpreting `collect`'s contact result: it records no-contact, grasp, and release without altering normal task logic. It temporarily bypasses `keep_contact` only while deliberately opening the gripper and restores it immediately.
4. Only call a `collect` result healthy when no-contact and release are exactly flat at 34 mm and a deliberate contact has a non-flat depth pattern. Do not use `Plan True`/`Check True` alone as evidence: `collect` can be unilateral and its `min != max` guard is only a flatness check.
5. A representative normal `lift_can` or `lift_bottle` run is required after the renderer and sanity checks. A task planner failure must be classified separately from tactile failure.

## Tactile marker diagnosis

- The expected GelSight Mini marker output is a 9x7 grid: 63 unique points. At local 400x300 resolution it normally covers approximately x=55--345 and y=43--257. A grid compressed near the image center indicates a coordinate-frame error, not an acceptable visual result.
- UIPC gel vertices are world-coordinate data, while the nested USD/TiledCamera may retain its initial world pose. Reconstruct the moving gelpad frame from its constrained bottom vertices with a rigid least-squares transform; map current points to the initial frame before the static camera projection. This changes observation coordinates only and leaves UIPC/PhysX/task settings untouched.
- Capture the rigid-fit residual alongside marker coordinates. A sub-micrometre residual across t0/t1/t2 establishes that the anchors define the moving sensor frame reliably.

## RGB/depth moving-frame diagnosis

- The nested tactile TiledCamera did not follow the UIPC gelpad by default. Save its immutable initial ROS-frame pose, reconstruct the UIPC rigid transform from constrained vertices, and call `TiledCamera.set_world_poses(..., convention="ros")` before the tactile camera update. Keep marker projection based on the immutable initial camera frame; otherwise markers are double-transformed.
- Validate both translation and orientation in `scripts/analyze_tactile_validation.py`. In the corrected `collect` test, position error was 9--48 nm and orientation error 4--12 microdegrees; this validates the camera frame rather than merely an image appearance.
- A moving camera sees the GelSight visual mesh unless it is hidden for its own RGB/depth readback. Hide **all** visual gel meshes while each tactile camera reads and restore their original visibility immediately afterward. Hiding only the local pad left the right camera seeing the opposite pad through the narrow gripper opening.
- The all-gel readback check produced the public-dataset semantics: both no-contact and release frames are exactly 34 mm; contact yielded a genuine 27.835--34 mm pattern. Toggling this USD visibility is renderer-only and must not change UIPC/PhysX state, collision settings, or task criteria.
- `scripts/collect_data.py --validation-tactile-sanity` writes `tactile_sanity.json`. The `collect` prism seed 3992 demonstrates a valid right-pad contact but is unilateral, so its bilateral criterion deliberately remains false; it is not a regression of no-contact/release behavior.

## Known validation status (2026-09-02)

- The authored tactile cameras now synchronize their pre-authored USD clipping planes to `(0.024, 0.034)` m. The RTX annotator and height-map agree within roughly 1 micro-metre; no-contact/release are flat at 34 mm. This is an observation-path fix only, not a mechanics change.
- Both pads use separate `gelsight_mini_case_left/right` links, the Isaac Sim 6 USD-collision fallback, and 83 UIPC constrained vertices each. Attachment callbacks have zero generation lag. `SoftPositionConstraint` applies the configured strength as a mass-scaled positional energy, so there is no hidden weak/default constraint to tune.
- The pinned PhysX `get_link_transforms()` API and Isaac Lab `transform_points()` both use `(x, y, z, w)` quaternions, while a USD `Gf.Quat` is `(w, x, y, z)`. The Isaac Sim 6 port made both conversions incorrectly: it reordered the runtime PhysX link to `wxyz` before the `xyzw` point transform, and used the USD `wxyz` quaternion directly to build local offsets with `quat_apply_inverse`. The two errors could cancel at initialization but rotated attachment targets incorrectly during motion. Convert USD orientations to `xyzw` before computing offsets and keep the runtime target path in `xyzw`; only the separate marker-camera `Pose` conversion needs `wxyz`.
- The former action driver called `write_joint_state_to_sim` for every CuRobo waypoint. That API teleports the robot state and velocity, producing 52--62 mm one-frame pad-target jumps, attachment errors above 30 mm, and a secondary CuRobo finetune failure. It is now used only at reset; normal motion writes controller targets through `scene.write_data_to_sim()` before physics.
- The collision world must match upstream: rebuild it before every query from the authored ground-plate mesh plus the current `can_d4`, `can_d5`, and `can_d6` point-cloud meshes, with collision activation distance `0.0`. The temporary Isaac Sim 6 port instead used a cuboid at x=-1000 and a 0.4 m activation shell, which removed environment collision checks and changed planned paths. A bounded probe confirmed the rebuilt scene-world is accepted by the pinned runtime with no conversion fallback or errors.
- With the corrected driver and collision world, `lift_can` seed 41 enters bilateral contact and all four rotate plans start without the former `FINETUNE_TRAJOPT_FAIL`. A capped run completed normally (exit 0, `OOMKilled=false`), peaking around 7.1 GiB and 156 PIDs under the 15 GiB/512-PID guard.
